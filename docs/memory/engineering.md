# Titan 可复用工程经验

更新日期：2026-10-28。来源：系统重构、恢复与账户模型修复、策略编译链向 Rust 的迁移、网格策略验收及管理平台实现与审查。

本文件记录后续开发应复用的设计原则和排障方法。执行环境以根目录 [AGENTS.md](../../AGENTS.md) 为准；涉及实现细节时核对当前代码。下方报告中的版本、路径和测试数量仅属于当次验证，不代表后续修改已经验收。

## 1. 按责任归属重构

| 责任 | 所属层与约束 |
| --- | --- |
| 编译调度、资源限制、超时、取消和子进程回收 | Rust CLI |
| 符号归一化、ABI 描述生成、链接与原生依赖审计 | Rust 编译链 |
| 策略编译结果序列化、摘要、签名、发布和加载校验 | Rust；复用同一套格式及校验规则 |
| 策略计算、类型化状态、Numba 类型检查和对象输出 | Python SDK；保持最小桥接协议 |
| 账户事实、恢复对账、订单执行一致性 | host、账户运行时和 connector 等平台层 |
| 配对关系、策略槽位、业务状态和风险决策 | `pair_arb` 等具体策略 |
| 报告生成 | 暂时保留 Python；不随编译链迁移扩大范围 |

- 用户编译入口统一为 `titan strategy compile`；Python 的 `describe`、`emit-objects` 是内部桥接协议。
- 运行策略和验证已有策略编译结果不应依赖 Python。离线 Numba 编译及可选报告可以需要 Python。
- 通用问题应在共同调用层修复，避免每个策略复制恢复、打包或校验逻辑。
- 删除旧实现时同步清理依赖、命令入口、测试及文档，避免两套事实来源长期并存。

## 2. 跨语言编译与策略编译结果安全

- 冻结策略源文件和参数输入；描述阶段与对象生成阶段使用相同快照、固定 `PYTHONHASHSEED=0`，并比较两阶段元数据，拒绝漂移。
- 把桥接输出当作需要校验的协议。检查 ABI 指纹、状态布局及 schema hash、回调与订阅、对象和符号名、导出集合，不能只检查进程退出码。
- 复用 Rust 加载端的 canonical CBOR、摘要及签名规则，避免 Python 再维护一份编码器或校验器。
- 审计最终原生策略编译结果的导出与依赖，拒绝 `Py*`、`numba_*`、`NRT_*` 等运行时依赖泄漏。
- 超时和 SIGINT/SIGTERM 必须清理整个进程组。只终止直接子进程会留下编译器后代进程。
- 原始 32 字节签名种子不能 `trim()`；首尾空白可能是有效密钥字节。仅文本十六进制格式可以去除外围文本空白。
- 私钥留在 Rust 侧，不传入 Python worker 的参数、请求、环境或元数据，也不写入日志。
- 发布前在目标文件系统暂存并完成校验。单 bundle 原子替换；成对文件最后提交 manifest，混合版本必须被摘要检查拒绝。
- 失败时保护原有输出；回滚失败时保留备份供恢复，不能清理掉唯一可用副本。
- 不为通过编译或恢复而放宽 ABI、schema、摘要及身份检查。ABI 不变也不代表新旧编译策略编译结果的摘要相同。
- 目标平台支持以实际工具链为准；本次验证的是原生 Linux ELF，不能据此声称支持跨平台编译。

## 3. 通用恢复与执行一致性

- 将恢复机制与策略业务状态分开。平台负责接收账户事实、重建状态和决定下单入口能否打开；策略提供必要业务状态及风险约束。
- 恢复不能仅靠“经济持仓看起来相同”。策略身份、策略编译结果摘要、绑定、状态结构、校验和及运行代次等仍需匹配；账户发生变化时应通过明确的对账流程处理。
- 缺少必要历史证据或对账失败时保持下单入口关闭，不以忽略 epoch/sequence 或清空策略状态替代恢复。
- 复合账户快照需要共同投影锁与提交边界。订单、持仓、余额各自最后一次更新版本不必相同，不能据此直接判断快照不一致。
- 事件回调与定时器回调采用一致的失败关闭语义；提交、checkpoint 或队列操作失败都必须阻止继续交易。外部派单前完成必要意图持久化与 flush。
- 提交 future 捕获账户 revision/epoch，在首次 poll 及异步交易所准备后、进入传输前复查。尚未发送的旧请求应拒绝；已经进入传输或结果未知的请求应走对账。
- 只要绑定账户，host 就必须接收账户事实，不依赖策略是否声明账户回调。
- 审查锁顺序与异步边界：避免持有普通 Mutex 跨越 await；跨 source/engine 锁的同步嵌套顺序发布可能死锁，应明确限制重入并保留源事件顺序。

## 4. 持仓模型尊重交易所语义

- 交易所决定账户持仓模式；项目负责完整表达和验证事实，不能用“返回记录超过一条”判断账户不可用。
- 以账户、品种和 position side 区分持仓，保留 NET/LONG/SHORT 及必要零仓位事实。不能简单把双向仓位合成净仓，丢失开仓价、保证金或平仓语义。
- 不根据空 REST 返回推断 NET 模式；没有事实不等于模式已确定。
- 合成零仓位使用 `exchange_ts=0` 等明确语义，不能填本地当前时间，否则缓冲中的真实交易所更新可能被误判为过期。
- 不完整成交更新不能覆盖权威完整持仓的数量、开仓价、PnL 和清算信息；需要完整账户快照的交易所应使用相应权威接口。

## 5. 远端验证工作流

1. 本地只编辑与审查。编译、格式检查、Clippy、代码生成及测试全部在 `192.168.3.88` 执行；实盘检查另走实盘服务器。
2. 同步前确认远端目录、代码身份与工作区状态。优先隔离目录，使用明确文件清单，避免覆盖远端修改或同步密钥、本地构建产物及 `.titan` 运行目录。
3. 无 `.git` 的隔离源码目录使用基线版本加源文件 SHA256 清单确认身份，不能仅以目录名称判断版本。
4. 同步清单包含测试需要的二进制 fixture、JSON/TOML 和用于维持空目录的 `.gitkeep`。先排除测试环境不完整，再判断业务回归。
5. fixture 来自编译服务器验证过的产物。固定策略编译结果摘要的配置与 fixture 必须一起维护，不能随意重生成其中一项，也不能上传本地构建产物替代。
6. 复用远端虚拟环境时检查 editable install 是否指向旧目录；显式设置 `PYTHONPATH` / `TITAN_STRATEGY_SDK` 指向本次源码。
7. 按变更范围验证：Rust 格式、检查、Clippy、测试与 doctest，Python SDK 和报告测试，真实 AOT 编译、签名校验、篡改拒绝、恢复及 CLI smoke。参考 [验证脚本](../../scripts/verify_system_refactor.sh)。
8. 保存命令退出码、日志、工具链版本、源码清单和 fixture 身份。新修改需要新证据，历史通过数量不能替代重新验证。

依赖下载受阻时优先保持 lockfile。确有缓存源码归档时，核对 lockfile 校验和后可传至编译服务器缓存，由服务器构建；不使用本地二进制，也不为绕过网络问题随意升级依赖。

被 ignored 的交易所测试需要逐项区分公网访问与真实账户操作。非实盘回归通过不代表真实交易所已验收，不能直接统一开启 `--ignored`。

## 6. 测试与排障经验

- 跨语言迁移后，让测试使用正式 Rust CLI；把打包、签名与校验测试迁到 Rust，保留 Python 的策略、Numba 和 ABI 桥接测试。
- 使用真实原生策略编译结果验证完整链路，同时覆盖输入漂移、非法元数据、错误签名、篡改、失败保留旧输出、超时和真实信号终止。
- CLI 测试核对实际 JSON 包装及字段含义；错误类型也属于接口约定，不能在迁移中无意改变。
- 通知已收到不等于资源已释放。EventEngine 测试中，消息送达可能早于 delivery 析构；应停止并 join 接收线程后断言引用归零，避免增加 sleep 或放宽断言。
- “Clippy 命令成功”不代表没有 warning。需要无警告门禁时使用 `-D warnings`，优先处理锁跨 await、错误体积和不必要复制等有运行影响的问题。
- 修复测试环境、测试同步和业务代码缺陷时区分原因，不因测试偶发失败盲改生产逻辑。

## 8. 统一网关的协议边界

- Gate CrossEx 保留 `EXCHANGE_BUSINESS_BASE_QUOTE` 原生身份；统一网关中的多个底层所仍是不同品种绑定，不能从相同基础币简称推断路由。
- REST 操作返回身份可能只表示受理。下撤改单应补查实际状态，补查失败标记结果未知并交给平台对账，不伪造订单终态或重试写操作。
- CrossEx 私有事实来自 `payload`，且推送也使用 `event=subscribe`；公开行情事实来自 `result`。握手确认与数据事实必须分别处理，全部私有订阅确认后才开放 bootstrap 屏障。
- CrossEx REST 订单和统一输出按基础币表达；公共推送的底层单位需单独核对，见下方实盘经验。废弃的 `contract_size` 不能用于换算。有限档盘口推送是完整替换快照，没有增量序号时明确使用零序号。
- 资产按底层所和币种返回时，向单币种账户 ABI 发布前需要聚合完整事实；单所增量不能覆盖总额。折扣保证金估值不能反推钱包余额。多币种总额使用新鲜的实际汇率，缺少汇率时拒绝估值，不混加不同币种；USDC 也不能默认与 USDT 等价。
- 验证证据：[CrossEx broker 迁移与公开行情验证，2026-10-21](../verification/2026-10-21/gate-crossex/README.md)。该阶段私有账户和交易仅经模拟验证；后续实盘证据另见本节最新记录。

- CrossEx 成交的累计均价和新增成交价必须分开；重连时累计量与累计金额基线要共同更新，并防止旧 REST 覆盖新 WS。CancelAll 应继续处理单笔失败并核对最终挂单。
- 资产/利息触发的权威刷新应放到会话持有的后台任务，合并请求、设总超时；断线必须取消旧任务，不能阻塞订单接收和 Ping。
- CrossEx 公共频道不保证订阅确认；公共快照以所请求原生品种的数据收齐为完成条件。原生 symbol 可包含中文及混合大小写，不能一律大写或限 ASCII。
- PositionChangedV1 的 64 位损益占用 88..96，币种 ID 应从 96 开始；只验证解码器和编码器是否一致不足以排除字段重叠，回归还需验证相邻字段互不覆盖。
- 本次补齐后的新证据见 [CrossEx 完整迁移与回归](../verification/2026-10-21/gate-crossex-complete/README.md)，早期通过结果仅作为历史。

- 实盘核对发现 CrossEx 的 GATE/OKX FUTURE 公共盘口、BBO 和成交推送保留合约张数；REST 下单仍为基础币。行情单独使用原生线性合约元数据换算，不能沿用 REST 的乘数 1，也不能从 lot_size 猜合约面值。盘口字符串须精确十进制乘法，浮点乘积的尾数会被 MarketService 的精确 lot 解析拒绝。
- 变更驱动的公共频道不一定提供查询时需要的首条快照；Gate OI 查询使用官方公开 futures ticker 的 total_size，并以查询接收时间标记观测时间。不能用超时后的零值冒充空持仓量。
- CrossEx risk_limits 必须带 symbols；原项目无参数包装不能直接照搬。实盘检查应使用真实参数，模拟 HTTP 路由测试也要断言必填 query。

- 浮点 tick/lot 计算结果即使对齐也可能带尾数；通过对齐校验后须按规则精度输出十进制请求。精度计算不能把 1e-9 步长当成整数。
- CrossEx 改单受理后，首次 REST 查询可能仍是旧价格或数量，update_time 更新也不证明字段已生效。仅轮询事实直到所请求字段匹配；限定确认时长，冲突终态或超时交给平台对账，不能重发写请求。

- 最新验证证据：[Gate CrossEx 受控实盘验收](../verification/2026-10-21/gate-crossex-live/README.md)：最终全仓库 507 passed、12 ignored；指定 Gate 账户 BTC USDT 的 post-only 下单/改单/撤单及私有 WS 确认通过，零成交与零残留。真实成交、其他底层所和长期稳定性仍需独立证据。

## 9. 行情热路径与本机延迟测量

- 热路径先从 WS 帧内借用十进制字符串，合约面值在会话启动时编译为精确比例。公共 MarketEventBridge 可将带显式数量乘数的借用视图直接写成 ABI 整数 lot，避免中间 String 和浮点乘积。不同 broker 的路由、序号、校验和及恢复语义保留在各自协议层。
- 借用只持续到同步 arena 编码完成；PRIMARY 异步队列持有已编码的 arena lease，不能持有原 WS 帧切片。转义字段或不匹配的消息可退回兼容解析，无效数量仍拒绝发布并恢复。
- 本机 WS 到策略延迟的起点放在完整 WS 帧返回后、JSON 解析前，终点放在真实原生策略回调入口；同机时钟差不使用远端行情时间戳，不包含网络。策略队列和视图转换属于该区间，不能与纯 ABI 函数调用的纳秒基准比较。
- 分配审计单独放在预热阶段，正式延迟窗口关闭计数；分别报告整个探针进程的 Rust alloc/realloc 与逐档字符串消除，不能宣称整条协议/运行时零分配。
- 其他 broker 不能直接照搬五档盘口的固定容量。原生 Binance 的 1000×2 档快照需要至少 48052 字节的 MarketBatch，并需核对策略视图条数上限；事件池、策略市场视图、回调记录容量是三种不同预算，不应统一调大全局常量绕过。
- 最新实现、回归、真实 V13 回调对照和适配边界见[Gate 本地处理优化](../verification/2026-10-21/gate-crossex-local-optimization/README.md)。

## 10. 策略停止的业务确认

- 无活动订单、无待交付成交不一定表示策略已完成停止；还可能等待平仓退避、独立成交交付或持仓投影。需要这些确认的策略声明 `STOP_BARRIER`，完成后调用 `ctx.complete_stop()`；宿主在此之前保持 Stopping，超时失败。能力写入 manifest，旧宿主拒绝未知能力，不能静默忽略新语义。
- 离线 adapter 和 CLI 遵守同一屏障。trace 可包含显式 stop 及后续确认事件；缺少停止证据时不能产出 COMPLETED 结果。
- 订单终态可能先于独立成交，持仓也可能先反映已知成交。业务账本等独立成交再消费，不从订单累计量推造价格或收益，也不提前释放剩余风险预占。
- 终态后等待成交的超时从收到终态开始计算，不从原始挂单时间计算；长时间正常挂单不应在首次终态到达时立即超时。
- V13 成交回调未提供手续费和资金费；网格配对账本只能声明毛收益，净权益及净亏损保护继续由平台账本/风控负责。
- 本次仅做离线验收，证据见 [Numba 网格及停止屏障验证](../verification/2026-10-22/grid/README.md)。

## 11. 网格成交竞态与证明式恢复

- 订单累计量、独立成交消费量和持仓确认是不同水位。账户全局序号不能证明某个未知订单的成交已被策略消费；终结意图应保留有界的逐订单消费记录，证据不足时交给公共对账。
- 完全成交后的撤对手单不应等待持仓推送；下一轮新增风险仍必须等独立成交和持仓一致。迟到旧成交不能用到达顺序覆盖有更高权威序号的锚点。
- 缺失的部分成交、终态、持仓投影及受理后无结果的 IOC 都需要有界等待；行情过期不能停掉确认时钟。撤单期限从本策略的发送时间计算，不能跟随无关订单刷新不断延后。
- 已确认库存的减仓先扣除尚未释放的反向订单预占，设置 reduce-only；该部分不应依赖开仓保证金。低/负可用余额仍可尝试合法减仓，不能为满足最小量扩大退出数量。不可交易尾仓应在新增风险前暴露。
- 人工留仓停止、风险停止和边界完成应保存不同原因。风险停止不继承人工留仓策略，恢复也不能将已触发的风险结束当作普通暂停。
- 公共恢复对账完成后，可以通过显式 `RECOVERY_ORDER_RESULTS` 能力向 Recover 回调提供只读结果。只有身份和已消费累计量匹配的终态证据才能释放意图；订单不在活动列表本身不是撤单证明。回调不发命令，恢复门仍由平台控制，旧宿主拒绝未知能力。
- 本次 schema 增加字段后升级为 2，不隐式迁移旧 checkpoint。验证包括 105 项 SDK、144 种消息排列、512 项 Rust 回归及真实原生宿主停止/恢复探针，证据见 [Numba 网格全面复核](../verification/2026-10-22/grid-review/README.md)。

## 13. 管理平台需求边界

以下是 [管理平台需求 v0.2](../management_console_requirements.md) 确定的设计约束。M1 离线闭环已实现并在编译服务器验收，见 [M1 证据](../verification/2026-10-23/management-console/m1/README.md)；M2/M3 另有独立验收，不能把 M1 或既有底层验证当作实盘管理能力的证据。

- 按接入展示、管理应用、节点执行、现有业务引擎划分逻辑边界，先采用一个管理服务和每节点一个执行进程，不为每项功能拆服务或 crate。
- 管理应用统一授权、审计和 Operation；节点负责本机进程与幂等回执；runtime 确认策略/账户状态。管理模式 CLI 与页面经同一应用入口，避免双重控制。
- 各操作共用一套记录和待执行列表。节点受理证据和 runtime operation 是同一管理操作的执行回执，不再引入平行 Job 状态机。
- 参数、策略编译结果、收益、风控和恢复规则只有对应引擎的一份实现。管理端保存只读结果，不重新记交易账本；worker 控制适配只调用已有生命周期服务。
- 构建与实盘节点共用协议、按角色开放能力；失联不推断仓位已清空，也不自动释放占用或启动副本。首期不引入通用工作流、消息总线、独立调度中心或分布式锁服务。
- [Web 技术方案 v0.1](../web_console_technical_plan.md)采用 PureAdmin 官方精简版、Vue 3/TypeScript、Rust Axum、REST/SSE 和同源静态部署，M1 已接入会话、离线业务及快照订阅。复用模板的请求与状态设施，Rust DTO 生成前端类型；页面只展示引擎指标，操作受理不等于业务完成，断线通过同一 Operation 与快照重同步恢复观察。新增验证按该方案第 10 节执行，当前已验证范围见各阶段证据。
- [管理平台实施计划 v0.1](../management_console_implementation_plan.md)按 T01 至 T17 安排 M1 离线闭环、M2 实盘只读、M3 生命周期操作；状态与证据在计划中维护。M2 先建设同一 worker IPC 的查询能力，M3 扩展控制，避免重复入口；M1/M2/M3 均已通过；M3 包括 100 USDT 上限的有限实盘控制与恢复验收。

- 缓存摘要只证明文件身份，不能证明它对应登记的原始 CSV。数据准备必须在独立目录成功完成、验证源文件未漂移并持久化回执后，再发布缓存；回放核对同一准备回执与完整输入快照。
- Snapshot 与 SSE 并发时按资源修订合并，旧 REST 回复不能覆盖较新事件；身份切换用本地代次丢弃旧请求与订阅回调。断网和心跳过期明确降级，重连沿用游标或重新同步。
- 任务标准输出和日志都须有严格容量上限；后台排空管道，超过上限终止并确认清理。受理回执不明保留 unknown；只有节点明确证明受理前容量拒绝，才继续排队。
- 原生 TradingRuntime 自有执行器的创建、关闭及析构必须由同一个同步线程持有。仅将 shutdown 包入 blocking 任务仍可能在异步上下文析构执行器并 panic；管理 worker 使用统一同步 owner 包裹完整生命周期。进程死亡而终态回执丢失时显示 UNKNOWN。
- 观测事实通过有界非阻塞队列交独立 SQLite writer；清洁关闭标记、溢出和失败必须进入完整性。成交按原生身份去重、冲突保留首笔并诊断；单位随事实固化，不因新配置重新解释历史。跨币种不直接相加，未证明的 notional 和策略净收益保持缺失。

## 14. 管理控制与跨服务事件身份

- 行情与账户不能分别从逻辑 ID 推导 EventEngine source ID；相同 ID/序号会被引擎当成重复而静默丢弃。事件引擎统一分配有界、生命周期内不复用的流身份，连接替换也分配新身份；策略绑定读取实际行情流身份，不重新计算。来源容量耗尽拒绝新建，不回收仍可能有迟到事实的序号空间。
- Pause 是显式策略编译结果能力。回调和确认时钟继续运行，通过 context flags 告知策略暂停；host 同时限制新增开仓命令，允许撤单及 reduce-only 保护。仅关闭交易门却继续调用不知暂停的策略，会把正常事实回调变成故障。
- A 只拥有全局受理和占用，N 只拥有进程及文件，E 拥有实际 runtime operation。超时后查询相同 E 回执或原 worker；只读查询不能补执行动作。调用前已记录但缺少调用后证据时，不能重派。Stop 为同一原生 operation，重复请求不能延长原停止 deadline；回执容量须为 Stop 保留余量。
- 原文件恢复阶段以原始字节 SHA256 固定 checkpoint；现已在第 19 节的 M1 实现中迁入 SQLite，保留同一字节摘要及旧策略编译结果/schema/绑定校验。节点控制期限使用 boot ID 与 CLOCK_BOOTTIME，恢复沿用原期限；系统重启、耗尽或连续性无法证明时拒绝，不以新的 wall clock 期限替代。
- 账户占用同时约束账户/品种与账户/策略订单命名空间。Recover 受理后，旧运行的迟到安全快照不能释放新操作占用；新运行登记时再转移所有者。只有证明 Start 从未尝试激活时，失败 Start 才可释放预占。未知状态不属于订单终态。
- 意图先落盘再派单；慢盘导致 flush 超时须关闭交易门并保留诊断，不得通过去掉 fsync 通过验收。构建与有限控制验收顺序执行，避免同一编译机的磁盘争用掩盖业务结果；运行配置的 handler 预算要覆盖所选持久化路径的实测延迟。拆除运行时前先持久化 E 的最终事实，拆除失败也应留存。

对应实现、故障与发布证据见 [M3 验证记录](../verification/2026-10-23/management-console/m3/README.md)，后续修改须重新执行相应门禁。

- M3 最终证据：全仓库 556 passed、13 ignored；SDK 113 项及原生/浏览器矩阵通过。指定账户的 23.348 秒验收中六笔最小委托均撤销，零成交和残留；代次 1 到 2 恢复保持原期限，安全证明释放占用，全部验收进程退出。成交竞态与有仓位平仓由本轮原生模拟探针覆盖；本轮实盘未发生成交。

## 15. 管理模块复核后的执行与观测边界

- 独立成交只确认消费量，不能代替持仓投影。受控执行从一致种子建立逐账户/品种/持仓方向的预期库存，以独立成交累计增量推进；数量匹配前禁止开仓，允许撤单与保护性 reduce-only，checkpoint 和安全释放同时保留这一屏障。无关账户全局序号不能解除屏障。
- Stop 的缓存身份只在成功进入 E 控制队列后成立。A 的受理预算、派发和旧回执核对，以及 N 的进程槽位，均为 Stop 保留独立有界容量；目录故障或普通任务积压不能阻断新停止。
- unknown 是回执分类，不是存活进程证明。PID/启动时间证明任务已死时释放计算槽位，保留原操作和账户占用；同一操作不能换身份重派。
- 多个核对循环的“不确定”回执以 Operation 修订做条件更新，不能覆盖节点较新确认的“受理前容量拒绝”。跨进程恢复对未决 checkpoint 意图经原账户接口只读补查，缺少或矛盾的终态继续拒绝；不能靠等待新 checkpoint 偶然避开未决意图。
- SQLite 记录源的存活由持有到最终 clean marker 的操作系统锁证明，不凭 `clean=0` 判断另一个健康 writer 崩溃。真正的缺口按来源及账户范围记录，历史无法证明的缺口继续保留。
- 金额敞口由 E 用显式线性计价币、绑定单位和新鲜 BBO 计算，与交易准入共用 tick/lot 算式。账户快照读取前后若意图或库存证据变化，该次组合观测不标为完整；最大值只声明持久化采样观测最大值，缺失行情和意图证明不补零。
- Web 目录、活动资源、各类历史及当前选择分别保留有界缓存；历史事件增长不能淘汰表单正在使用的模板、绑定和资源。

修复与新验证证据见 [M1/M2/M3 复核修复](../verification/2026-10-23/management-console/review-fixes/README.md)。

- 本轮修复验证：全工作区 565 passed、13 ignored；SDK 113 项、M3 21 项模拟及 M1/M2/M3 页面通过。指定账户 20.829 秒实盘复验中四笔最小委托全部撤销，零成交、挂单和仓位，采样最大含在途上界 16.3664 USDT；非终态 checkpoint 经真实订单补查恢复，沿用原期限。首次私有流 bootstrap 失败正确关闭，候选未激活且原占用保留，清理后相同产物重新验收通过。新金额估值配置不改变旧成交去重指纹。

## 18. 策略身份与独立业务观测

- 策略是唯一业务主体。参数版本、策略版本、运行、部署、回测、报告和恢复点都从属于策略；编译结果不再作为独立管理对象。完整定义见[策略身份与业务观测协议](../strategy_observation_protocol.md)。
- `strategy_id` 表示稳定业务归属，`strategy_type` 表示 `grid` 等实现类别，`source_version` 是作者版本号，`runtime_strategy_no` 是运行时路由编号。运行代次与宿主会话分别命名，不以文件摘要代替策略身份，也不因改名重编号订单命名空间。
- 当前参数编译进原生程序，可运行策略版本必须固定源码、参数和编译结果。编译内容校验值、传输文件 SHA256 与原生库 SHA256 分别表达，不相互替代。
- 业务观测 schema 只包含公开字段、类型、单位和语义。私有投影随策略编译内容签名，由 Rust 校验并解析内部路径；公开 hash 不包含恢复布局、路径或偏移。管理器和页面只消费公开字段，不再解释 `data.grid`、`data.config` 等恢复布局。
- 业务观测在成功回调边界独立发布到预分配原始标量内存帧，宿主冷路径只复制帧再格式化，不读取恢复文件。无请求时只检查原子标志；请求合并，有请求时最多复制 1 KiB 原子标量，使用顺序一致的帧版本和载荷校验完整性，写方不加锁或重试；读取方最多重试 8 次，暂停读取不阻塞交易线程或丢失终态帧。恢复点持久化周期和屏障独立保留。恢复结构变化后可以继续输出相同观测协议；观测兼容绝不放宽原编译内容、状态结构、绑定和恢复证据校验。
- 有效条件不满足的可空字段不补零；无效枚举和非有限值标记字段缺失及观测不完整。平台账户事实、实际持仓和财务口径继续由平台维护，网格只导出自己的阶段、锚点、配对毛收益和期望库存。
- 公共 schema 的规范化表示与 hash 必须一致，不能让统一的大整数转换再次改写 schema 版本字段。心跳、采样时间、业务源水位分别表达；重复读取同一内存帧不推进发布序号；v2 source 明确使用发布序号、成功回调水位、采集时间与运行代次，不作为恢复证据。
- 旧签名文件和恢复点先按原字节验证再作内存字段适配，历史 ID、冻结记录和摘要保持原值。v2 查询仍在授权和策略归属过滤后分页，未知观测协议只做有限通用展示。
- 本轮验证记录见[策略命名与观测解耦](../verification/2026-10-27/strategy-observation/README.md)；验收状态以该记录为准，不沿用旧报告证明本轮修改。

- 发布请求的认领点是原子交换；认领之后到达的请求必须留给下一成功边界。重复回调水位不认领请求，未启动、恢复就绪和回调水位 0 不发布。业务帧的值、条件和来源共同校验，不能只测试值相等而遗漏有效条件或时间水位。取时等外部调用放在帧版本变为奇数之前。
- 失败路径须统一撤销观测：特别核对手动恢复点提交、停止 flush、执行结果队列拒绝和失效控制队列拒绝。关闭交易门不能只是可逆的 bool 写入；终止失效必须在同一原子状态上阻止迟到的 Start、Resume、Stop 及回滚路径重开，且不能依赖失效操作成功入队。拒绝的控制操作须结束，失效须结束待完成的停止操作。
- 查询和页面校验都以运行记录的代次为准，同时匹配策略运行编号；不能用候选观测自身的代次替代查询运行的身份。业务帧一致不等于运行、账户和观测的全局事务一致。
- 成功停止和通道关闭后，迟到执行回执不得把已经排空的运行重新标为失败或撤销终态观测；停止完成前的队列拒绝仍须失败关闭。异步完成侧用运行级原子停止标志识别该边界，避免为了检查生命周期而重入回调持有的锁。

## 19. SQLite 恢复与本地事实持久化

2026-10-27 完成 M1（P01–P04）和 M2（P05–P09）：恢复点/代次统一进入 SQLite，模拟运行与回测共用本地事实、查询和对象端口。完整约定见[数据持久化设计](../data_persistence_design.md)，任务及验收见[实施计划](../data_persistence_implementation_plan.md)，维护语法见[恢复存储](../recovery_storage_operations.md)和[本地历史与结果](../local_persistence_operations.md)。2026-10-28 完成 M3（P10–P13）真实驱动、往返切换及软件故障/预算验收；同日完成 P14 首轮指定账户受控实盘验收，[M4 记录](../verification/2026-10-28/data-persistence/m4/README.md)明确零成交范围。后续[真实成交补验](../verification/2026-10-28/data-persistence/m4-filled/README.md)未通过，用户明确要求保留占用、停止本轮复验。

- 策略只定义业务状态、决策及公开观测，不访问存储；Rust 宿主注入领域端口。切换存储不修改策略 ABI，也不重新编译策略。平台财务事实和策略业务状态仍分别归原层维护。
- 恢复点、最新 head 和代次统一进入执行节点本地 `runtime.db`，与历史及管理数据库分开。正常运行只有 SQLite writer，文件仅作显式导入导出，不在 SQLite 失败时自动回退。
- 保留原始恢复载荷为不可变 BLOB 和 SHA256，旧字节先校验后解码；不因数据库迁移重写旧请求、摘要、身份或私有状态。固定记录引用与 pin 保证受理后不漂移，观测独立采集公开帧，不解析恢复 BLOB。
- 运行代次独立事务预留且永不回退；完整业务状态与未决意图同事务提交，指定提交确认后才允许派单。超时或提交未知保持故障关闭，交易所结果未知继续通过原身份对账，数据库事务不提供跨交易所的 exactly-once 保证。
- SQLite 事务锁不能替代宿主生命周期独占锁、管理账户占用及进程身份。旧备份可能回退代次及交易证据，恢复后必须证明安全下界和账户事实；不足时保持交易门关闭，不能新建 namespace 绕过检查。
- 新代次预留即隔离旧代次，不能等新 head 出现才拒绝旧写入。条件推进 head 必须影响一行，否则完整事务回滚，不能确认一个没有发布 head 的载荷。
- 服务停止后 EventEngine 可能仍保留运行及存储 Arc。必须显式 `close(deadline)`，排空并 join writer 后再释放 namespace 锁；关闭超时保留锁。不能用“服务已 quiesce”推断 Arc 已析构，也不能先释放锁再后台落旧状态。
- namespace 锁文件只保存 `store_id` 身份见证，不保存状态或代次；它能发现数据库被删除重建，不能证明同一身份的旧字节没有被原位覆盖。数据库绑定规范化位置，硬链接和移动副本不能直接激活；Backup API 副本标记不可激活。绕过工具覆盖旧库无法自动安全恢复。
- 旧目录只有 `.generation` 而没有恢复点时，使用 `import-generation` 保留失败启动消耗的代次；不能按旧恢复点代次猜测下界。正常启动核对旧文件原字节对应的导入回执，没有回执拒绝，不做自动迁移或双写。
- 固定 `rusqlite=0.40.2` / bundled SQLite 3.53.2，并在恢复连接拒绝低于 3.51.3 的运行时，确保包含上游 WAL-reset 修复。该升级用于解决已确认的多连接 WAL 耐久风险，不是网络或编译失败的替代方案；保持 lockfile，验证所有 SQLite 使用者。
- 历史事实使用有界 writer、业务去重、持久化水位和来源缺口。完整回测审计采用流式背压；异步实盘采集崩溃丢尾须明确标记，不能声称天然零丢失。策略恢复点不等于完整撮合器和数据游标快照，本期不承诺任意中断回测续跑。
- M1/M2 本地 SQLite/文件对象，M3 已实际验收 PostgreSQL 历史投影与 S3 兼容对象切换。执行恢复仍保持节点本地 SQLite，其他恢复后端须单独验收。设计接口不等于驱动已支持。
- M1 的本轮证据见[SQLite 恢复验收](../verification/2026-10-27/data-persistence/m1/README.md)。性能报告区分 `FULL` 提交原语与完整回调；不能沿用内存或旧文件指标，也不能关闭 fsync、放宽原期限来达标。本轮没有真实账户连接或实盘部署。
- M2 的 `titan-persistence` 不依赖账户服务、Runtime 或 CLI；账户及引擎生产事实，CLI 组装适配器，策略/SDK 不获知 recorder。现有账户财务投影与统一 envelope 同事务写入，不能新增第二套账本。
- 来源须在第一批事实前登记范围并持有所有者锁，零条记录也能识别未关闭来源。旧表发现未清洁来源时追加缺口，不重新打开已封存的 archive source。事实、水位、去重和两个 clean marker 保持各自同事务；COMMIT 后才更新 durable row。
- 停止时先递增 pending 再检查 closing，保证已接受生产者不会越过 writer 的最终排空。必需队列丢弃或 writer 失败拒绝清洁关闭；身份冲突单独标记 integrity failure，不能误作 writer 崩溃。关键审计失败在构造新单传输 future 前拒绝，撤单仍可用，已在途请求继续按原身份核对。
- 公开帧按原发布序号冷采样，重复读取不制造业务事件；账户事实未知策略归属时保留 null。完整回测审计有界背压，权益采样仍须显式 sampled，收到的片段完整不代表交易所历史或连续曲线完整。
- 历史查询先授权再分页，独立只读连接、固定上界和过滤/方向绑定游标。权益图读最新记录，不能沿用升序第一页导致长期运行后停在最早 20 条。schema reader/writer 均拒绝未知版本；历史、恢复、管理和对象目录角色不能混用。
- Parquet 保留 UInt64、负时间、原始单位和浮点位值。JSON 转回事实再归档时启用 `serde_json/float_roundtrip` 并核对 SQLite/Parquet 有序原载荷摘要，不能只比较近似数值。普通行情采用有界分片，原生历史扫描流式；CSV 准备排序和轻量 trace JSON 加载仍沿用原内存流程。
- 内容对象按 SHA256 校验，不把 ETag/路径当摘要。结果与数据准备在打开目录数据库及登记前保存 pending 原字节凭证；修复只重试发布/登记。v1 清单保留原字节、manifest 最后提交，物化复制而不建可写硬链接；报告不重算收益。
- [M2 最终验收](../verification/2026-10-27/data-persistence/m2/README.md)：540 个源码文件字节一致；34 个步骤、636 项 Rust、2 项 doctest、SDK 115 项、报告 5 项、32 项回环流程和全部浏览器通过。18 组共 5,468 笔模拟成交，42,743 条 SQLite/Parquet 事实一致；同一原生文件切换输入格式不改变引擎及事实。[性能](../verification/2026-10-27/data-persistence/m2/performance.json)的 FULL 提交 P99 13.107 ms、原生回放峰值 RSS 20,248 KiB 不作为生产 SLA；生产预算、配额/保留和完整争用门禁留 P13，本轮没有真实账户连接或部署。

- M3 的配置控制库保存不可变 profile、目标 UUID、CAS 路由修订和维护回执；秘密只取环境变量引用。配置锁见证初始化状态，控制库丢失、同路径换库或目标身份不匹配拒绝，不能静默回默认目录。新游标绑定控制实例和修订，初次本地来源登记不冒充后端切换。

- v1 结果中的 `history.db` 是不可变快照；从 Backup API 创建的 `history-source.db` 承担投影/裁剪/回填，不能在已发布文件上直接删行。控制库保持无长事务的读连接，避免短连接最后关闭引发 WAL 生命周期竞争；冷路径只重试可识别 SQLite 锁错误，不重试 I/O/未知提交。

- 新 SQLite 运行编码载荷最多 2 MiB、默认队列 16、回调准入至少 750 ms；通用 5 ms 默认保持原值但拒绝 SQLite 注册，不能自动延长既有恢复/停止期限。默认事实 DB+WAL 20 GiB/库、最低余量 1 GiB、本地对象 100 GiB/单对象 5 GB，账户采集同时按 4,096 条和估算 16 MiB 限制；达到门槛故障关闭，保留到显式维护或容量门槛。
