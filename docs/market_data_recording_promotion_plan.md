## 4. 长文版（X Article / Premium 长贴）

**标题**：基于二进制+差分+快照的订单簿采集方案

**副标题**：同样 8 小时，落盘小 10.5 倍，数据可复核

```text
回测做得越多，越会发现：策略不是最贵的，可信的数据才是。

我们重写了行情采集，目标只有三个：体量可控、数据可复核、回放够快。

【怎么做】
100 ms 网格 + Top-100 盘口净差分。
每 60 秒一个块，块首存一次完整快照，块内只存每个槽的变化；
一小时一段，价格与数量全程整数化，不经过浮点。
60 秒块不是随便定的：此前每个 100 ms 槽都写一块、每块重复一次全量快照，
8 小时数据里 96% 的字节是重复快照。改成 60 秒块之后，同样 8 小时，
book 从 601 MiB 降到 46.9 MiB，写盘块数从 55.6 万降到 991。

【怎么证明数据没问题】
三道校验：块内 CRC32C；块间“上一块末状态 = 下一块首快照”逐档比对；
录制端在线校验交易所序号链，断链立刻写入 gap 控制块并重新取快照。
此外用交易所 REST 快照 + 近期增量重建影子盘口，再做逐档对账。
每日生成 quality.json，只给 PASS / WARN / FAIL 三档；FAIL 数据在回放入口直接拒绝。
我们不追求“零 gap”的口号——交易所会强制断连，gap 一定会发生；
承诺的是“缺口一定被记录、可解释、可被回测处理”。

【一次拿全】
深度、逐笔成交、合约 OI/资金费/爆仓，在同一次录制里完成；
现货与永续共用一套目录、质量口径与回放接口。
已适配 Binance 现货/USD-M/COIN-M、Bybit、OKX、Hyperliquid。

【数字】
同样 8 小时、同两个品种、同一公开行情源：
新格式总落盘 53.7 MiB，旧 raw gzip 565.5 MiB（约 10.5×）。
回放探针 7.02M records/s，读 59.5 MB/s，压缩比 0.198。
600 秒实盘验证：21 个块，0 损坏 / 0 截断 / 0 gap，严格质量门禁回放通过。

【边界】
只记录 Top-100 窗口，不承诺全深度与逐笔队列位置；
合约用 aggTrade，成交条数与原始 trade 不可直接对齐；
REST 对账会如实标出少量不一致样本——这类数据不会被包装成 PASS。

下一步会开放样例数据集、Cookbook 和质量报告模板。
感兴趣的方向：更多交易所、更多合约辅助数据、回放性能。
```
