## 视觉方向

采用深色导航和浅色内容区，以低饱和青绿色标识主要动作。收益、买卖方向和告警有明确文字，不依赖颜色判断。边框轻、阴影少，减少通用后台模板的多层导航与嵌套卡片。

| 项目 | 设计约定 |
| --- | --- |
| 背景 / 内容 | `#f5f6f8` / `#ffffff` |
| 导航 | `#172430`，桌面宽 208px |
| 主文字 / 次文字 | `#202c3c` / `#68798b` |
| 主动作 / 正向值 | `#0a8375`，方向同时用文字标识 |
| 告警 / 危险操作 | 琥珀色 / 低饱和红色 |
| 字体 | 系统中文无衬线，金额使用等宽数字 |
| 布局 | 30px 页面内边距，14–20px 区块间距，12px 内容圆角 |
| 排版 | 页面标题 24–25px，主指标 25–31px，表格数据 12px |

以桌面操作为主：宽屏保留导航、主内容和风险侧栏；中等宽度缩减导航；窄屏纵向排列，完整表格在自身容器内横向滚动。图表在窄屏减少时间刻度，不裁切指标单位。

## 两个核心页面

### 运行总览

从上到下为当前账户与观测状态、摘要指标、账户权益与 BTC 风险、实例列表、恢复待处理提示。

- 摘要明确范围：账户净权益、已确认运行实例、**BTC** 活动委托、待处理数量。SOL 的未知委托不被算作零，也不冒充已完整确认的账户总委托。
- 账户权益只表达账户事实，不标为策略收益。风险卡明确是 BTC 的含在途上界；历史最大值称“采样观测最大值”。
- 实例列表提供名称/品种搜索和状态筛选。BTC 打开完整详情，ETH 与 SOL 用摘要抽屉展示本次设计覆盖的状态。
- 恢复原因可直接打开，不需要在原始 JSON 中寻找。

### 策略详情

顶部固定显示策略身份、品种、实际状态、目标代次，以及暂停、停止和诊断入口。主区域分为运行概览、订单与成交、参数与版本、事件记录。

- 概览：网格配对毛收益、策略净收益完整性、账户最大回撤、持仓；账户权益图、网格价格阶梯、活动委托、风险分解。
- 订单与成交：分别展示委托和独立成交，保留基础币单位、只减仓用途、最后确认状态。
- 参数与版本：冻结参数、制品身份、停止方式与 checkpoint 来源；不提供运行时热修改。
- 事件记录：按时间展现事实与管理回执，诊断和原始字段放入次级抽屉。

## 状态与交互

顶部“状态预览”可切换正常、观测过期和恢复待核对，路径支持 `?state=stale#/strategy/grid-btc-01` 与 `?state=recovery#/strategy/grid-btc-01`。默认首页为 `#/overview`，详情为 `#/strategy/grid-btc-01`。

| 状态 | 展示与操作 |
| --- | --- |
| 正常观测 | 正常事实和可用能力；策略净收益仍因费用归属不完整显示 `—` |
| 观测过期 | 显著提示最后确认时间，当前敞口显示 `—`，历史值标明口径；暂停不可用，停止按示例引擎能力保留 |
| 恢复待核对 | 交易入口关闭，敞口不可确认，账户占用保留，不自动重派动作 |
| 控制已受理 | 展示同一操作的待确认回执，不提前显示已暂停/已停止，不清零持仓或委托 |

确认框展示实例、代次、账户品种、最后确认数量及停止语义。暂停继续事实接收和保护性处理；停止沿用制品已声明的方式。**正式实现必须使用后端 `allowed_actions` 与统一授权，不从本设计稿的情景函数推导控制权限。** 观测过期本身不能一律禁用引擎仍允许的停止动作。

可预览的交互还包括：实例搜索/筛选、权益时间范围、图表数值提示、详情标签切换、事件与诊断抽屉、原始诊断折叠、暂停/停止模拟确认。抽屉和确认框支持 Escape、焦点圈定与返回；非本轮页面的导航标为不可用。

## 正式实施的边界

保留 Vue 3、Pinia、现有请求/SSE、精确数值处理与 Rust API，基础控件继续复用 Element Plus。设计稿的原生 HTML/JS 只是可审阅的视觉规格，不是另一套生产框架。

| 设计区块 | 正式接入来源 / 约束 |
| --- | --- |
| 实例、状态与操作 | 现有 Run 资源、`allowed_actions`、统一 Operation；受理与业务完成分别展示 |
| 账户权益、回撤、敞口 | E 输出的 financial 与账户快照；前端仅格式化，不新增计算公式 |
| 网格与持仓 | 策略业务快照与账户事实分别展示，不能互相替代 |
| 数量与价格 | 保留后端精度和单位；列表格式化，完整值可查看/复制 |
| 过期、恢复与完整性 | 复用现有 SSE/缓存修订、来源时间与诊断，不能只改颜色后继续视为实时 |
| 原始诊断、历史、日志 | 复用现有历史与日志接口，按需加载到次级入口 |
| 配对毛收益 / 策略净收益 | 分别取策略业务账本和有完整归属证据的引擎结果，缺失不补零 |

视觉确认后，公共导航、样式变量、格式展示、运行总览和策略详情已按该方向落地；策略参数、构建制品、历史回测与账户风险也已按相同规范完成。每阶段保留既有功能并在编译服务器验证，验收以对应实现的验证记录为准。
