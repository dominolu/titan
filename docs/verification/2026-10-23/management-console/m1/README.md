## 实现范围

A 的 SQLite Operation、幂等、固定输入、授权、会话、CSRF、审计、分页和 SSE；N 的本机 Registry、进程身份、持久回执、独立任务、取消与有界输出；SDK 的描述/规范化导出；历史回放的 ResultBundle 和权威曲线适配；PureAdmin 页面与同源部署已接通。所有实现位于既有 crate，不增加平行交易状态机。

缓存必须由成功的数据准备操作产生，回测核对准备回执、原始输入摘要和缓存摘要。准备失败不替换有效缓存。回测保留失败结果和最终仓位；留仓的历史网格任务明确失败。报告逐文件校验清单，前端仅格式化展示，原始精度保留在 API、详情和下载文件。

## 验证入口

- [固定检查脚本](../../../../../scripts/verify_management_console.sh)：Rust 格式、限定本 crate 的严格 Clippy、CLI/历史/SDK/报告回归、TS 生成、类型、ESLint、Prettier、生产构建。
- [真实 HTTP 夹具](../../../../../scripts/management_console_smoke.py)：启动真实 A/N，实际调用 Numba 构建和 Rust 全分辨率行情回放。
- [浏览器流程](../../../../../scripts/management_browser_smoke.mjs)：实际页面校验、冻结、构建、回测、报告，五页导航、刷新、断网恢复、大整数和同页面切换只读用户。
- [故障注入](../../../../../scripts/management_fault_smoke.py)：缺少准备证据、制品篡改、私有/符号链接文件越界、留仓结果、并发节点幂等、编译超时和会话过期。

完整矩阵为三段 BTCUSDT 行情 × neutral/long_bias/short_bias × base/stress，共十八组。先完成真实构建与矩阵，收紧缓存证据链后重新准备三个数据集，并使用相同冻结制品实际重放十八组；`--reuse` 复用制品，不复用成功结论。原始结果见 [results.json](results.json)，故障结论见 [faults.json](faults.json)，页面结论见 [browser.json](browser/browser.json)。

故障期望失败与验证本身失败分开记录。`unknown` 不作为终态或成功，失联不自动重派。A/N 重启过程中，同一编译操作继续执行，Registry 中仍为一条记录；节点并发重复受理也只产生一个进程。

## 工具链与限制

Rust/Cargo 1.94.1，Node 22.22.0，pnpm 10.32.1，Python 3.11.14；实际输出见 [toolchain.txt](checks/toolchain.txt)。PureAdmin 上游固定 `f0ff132561ab684bb78379239adf29f9a38ac7f1`，MIT 许可保留。浏览器使用 Chrome for Testing 156.0.8078.4，安装包 SHA-256 为 `c3e50596aef52c58f8fda3c6b3411c33d34c88b177b3ed1c2243359fd3b8ba20`。

全依赖 Clippy 曾遇到既有 `hftbacktest/src/backtest/data/npy/mod.rs` 两处 `needless_return`，未扩大本次修改范围；验收命令使用 `--no-deps` 严格检查改动所属 CLI crate。ts-rs 会提示忽略它不理解的 Serde `deny_unknown_fields` 属性，Rust 的反序列化约束仍有效；前端还有上游浏览器兼容数据过期提示。这些提示不能表述为全仓库零警告。

本期样本只用于管理链路和历史执行验证，历史参数风险规模与用户授权的实盘 100 USDT 上限无关。实盘部署、唯一占用、生命周期 IPC、事实留存与恢复仍需 M2/M3 的独立证据。`Start` 等动作虽然已纳入统一契约，M1 节点不开放真实交易写能力。
