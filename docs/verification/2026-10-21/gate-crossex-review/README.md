## 已确认缺陷

| 优先级 | 位置 | 场景、结果与影响 |
| --- | --- | --- |
| P1 | `stream.rs:594–600`，下游 `account_runtime.rs:1533` | 将新增成交数量与累计平均价组合成 Fill。先成交 0.005@100，再成交 0.005@200 时，第二笔实际价格是 200，发布使用的价格却为 150。订单累计均价与新增成交价格需要分别表达；合并成交可由累计金额差计算增量均价。 |
| P1 | `mod.rs:207–213`，`account_runtime.rs:1192–1242` | `track_managed_order` 只在 key 不存在时插入，忽略重连 bootstrap 提供的新累计成交基线。断线前已成交 0.004、REST 恢复为 0.006、随后 WS 累计变为 0.008 时，新增量错误算成 0.004，正确应为 0.002。下游与已提交投影的差值检查会失败，造成额外账户失效和恢复。需接收更新的权威基线，同时防止旧快照覆盖更晚 WS 事实。 |
| P1 | `brokerapi.rs:373–380` | CancelAll 在每笔撤单后使用 `?`，首笔已成交竞态或请求失败会立即退出，同品种其余挂单完全不再尝试撤销。停机安全策略可能留下其他可撤订单。应对剩余订单继续执行取消，收集结果并确认最终挂单状态。 |
| P1 | `stream.rs:243`、`stream.rs:456–459` | 私有 WS 接收循环同步等待每个 asset 推送触发的完整账户 REST 查询。模拟中将余额 HTTP 响应保持 pending，随后已送达的订单推送一直无法发布，直到 HTTP 响应放行。生产 HTTP 超时配置为 10 秒；期间流仍可处于 READY。应将完整账户刷新移出接收循环，合并刷新请求，并保持一致性/失效语义。 |

位置均指本次审查时的本地生产源码。前三项涉及成交事实、恢复和退出语义；第四项影响账户事件时效及对冲反应。原有普通用例没有覆盖这些条件。
