# 后续代码审查：三项问题已修复

初轮功能回归后进一步审查确认了下列问题。三项现已修复并在编译服务器重新验收，见[修复证据](../depth-review/README.md)。以下保留发现时的触发条件，不表示当前版本仍有这些缺陷。

1. **P1：E04 删除后补单漏记。** `strategies/orderflow_events/strategy.py` 的 `on_depth` 只在 `before > 0` 时调用 `track_touch`，但冰山补单需要识别已知删除后的 `0 → 正数量`。原生回调复现：价位删除后 `fills=1`，10 ms 后数量恢复至 10，`refill_ms` 仍为 0；`detect_e04` 因此无法触发。修复时区分本代次内已知删除与首次进入 Top100，并补充完整触发测试。
2. **P1：深度失效同时阻止保护性减仓。** `runtime_v13.rs` 对 `HOST_DEPTH_100` 的所有 `Submit` 执行统一拒绝，包括 reduce-only 退出；失败会终止运行，同回调中的撤单也无法提交。适用于同时声明深度能力和订单执行能力的策略。应保留撤单与经账户事实验证的减仓路径，仅阻止新增风险。
3. **P2：离线与在线执行准入不一致。** `OfflineV13Adapter::invoke` 无条件以交易门打开的状态调用 `invoke_staged_v13`，没有在线新增的深度有效性检查。同一策略在 `valid=0` 后提交订单，可能在离线被接受、在线被拒绝。应复用共同准入逻辑并验证有效、失效、恢复三个阶段的行为一致。

初轮审查只复现问题；后续修复新增了对应回归。旧验收数量保持历史事实，新的 666 Rust / 123 SDK 与六组原生在线、离线结果见修复证据。
