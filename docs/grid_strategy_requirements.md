# 生产级网格策略需求说明

版本：v1.1  
状态：需求确认阶段  
说明：本文只描述业务目标、功能范围和验收标准，不包含技术实现细节。

## 1. 项目背景

Titan 当前具备行情、下单、成交、持仓、手续费、资金费、回测和实盘运行能力，但尚未提供一套可直接用于生产的统一网格策略。

本项目需要新增一套高频网格策略，覆盖现货和合约交易。策略以基准价格为网格中心，只维护指定数量的活动网格订单，而不是把完整价格区间内的所有网格一次性挂满。新策略启动时自动计算初始仓位、成本和初始基准价格；订单完全成交后，以完成该订单的最后一笔成交价格更新基准价格。

## 2. 建设目标

- 同时支持现货和合约；
- 支持配置买卖两侧实际挂单层数；
- 网格随最新完全成交订单形成的基准价格更新，不要求预挂全部网格；
- 成交后能够及时补充网格订单；
- 支持独立成交事件处理；
- 分别统计网格收益、持仓收益和总收益；
- 控制持仓、资金占用和订单风险；
- 回测与实盘的核心行为保持一致；
- 异常退出或重启后能够安全恢复或停止。

## 3. 功能范围

### 本期范围

- 单策略实例、单品种；
- 现货和线性合约；
- 等间距动态网格；
- 每层可选择按固定数量或固定金额下单；
- 买卖两侧分别配置活动层数；
- Post-only 限价单；
- 净持仓模式；
- 回测与实盘；
- 网格、持仓和总收益统计；
- 基本风控、熔断和重启对账。

## 4. 网格业务规则

策略以基准价格为网格中心，在买卖两侧生成目标报价。基准价格遵循以下规则：

- 新策略没有可作为基准的初始仓位成交成本时，使用启动时有效盘口的中间价作为初始基准价格；
- 新策略执行初始化建仓时，使用完成该建仓订单的最后一笔成交价格作为初始基准价格；
- 接管或恢复策略时，恢复策略上一个完全成交订单的最后一笔成交价格；
- 策略运行中，只有订单完全成交后才更新基准价格；
- 部分成交只更新订单累计成交量、余额、持仓和收益，不更新基准价格；
- 没有新成交时，即使市场行情发生变化，基准价格也保持不变；
- 当前盘口价格只用于订单合法性、Post-only 检查、风险控制和持仓估值，不作为网格重新定位的依据。

用户可以分别指定：

- 买侧挂几层；
- 卖侧挂几层；
- 相邻层之间的距离；
- 每层下单数量或每层下单金额。

策略只跟踪和维护由本策略实例创建的活动订单：

- 其他策略、人工或外部系统创建的订单不属于本策略管理范围，策略不查询其网格归属，也不对其执行撤单或修改；
- 基准价格因订单完全成交而更新后，本策略原有且仍有效的未成交订单继续保留；
- 不因为原有订单偏离新的基准价格而撤单；
- 订单完全成交形成空缺后，以完成该订单的最后一笔成交价格作为新基准价格，按配置补充新的网格订单；
- 活动订单总数不得超过配置的挂单层数和风险上限；
- 只有策略停止、风控触发、订单本身失效或人工明确指令等场景，才允许撤销本策略创建的订单。

## 5. 配置需求

| 参数 | 说明 |
|---|---|
| 交易品种 | 策略运行的目标资产 |
| 市场类型 | 现货或线性合约 |
| 网格价格下限 | 策略允许创建网格订单的最低价格 |
| 网格价格上限 | 策略允许创建网格订单的最高价格 |
| 买侧活动层数 | 实际同时维护的买单层数 |
| 卖侧活动层数 | 实际同时维护的卖单层数 |
| 网格间距 | 相邻网格层之间的距离 |
| 每层规模模式 | `quantity` 表示按固定数量，`notional` 表示按固定金额 |
| 每层数量或金额 | 根据规模模式配置每层基础币/合约数量，或每层报价币名义金额 |
| 检查周期 | 检查本策略订单状态、风险和失败重试的时间间隔 |
| 最大名义金额 | 策略允许占用的最大交易规模 |
| 杠杆倍数 | 合约策略使用的杠杆；现货不适用 |

初始基准价格、初始仓位及其成本不是用户配置参数，由策略创建流程根据启动盘口、账户资产、网格上下限和初始化成交结果自动计算。手续费不由策略参数重复配置，以交易连接器或回测执行模型产生的实际费用为准。仓位上限不单独配置，由网格边界、每层规模、可分配资金以及合约杠杆计算得到。

其他参数必须满足交易所价格、数量、最小订单和最小名义金额规则。买卖活动层数不能同时为零，价格下限必须低于价格上限，杠杆必须满足交易所和账户限制。

## 6. 初始仓位与资金计算规则

### 6.1 变量定义

| 符号 | 含义 |
|---|---|
| `L` | 网格价格下限 |
| `U` | 网格价格上限 |
| `P0` | 创建策略时有效盘口的中间价 |
| `ΔP` | 网格价格间距 |
| `tick` | 交易品种最小价格变动单位 |
| `lot` | 交易品种最小数量变动单位 |
| `C` | 合约乘数；现货取 `1` |
| `Q` | 固定数量模式下配置的每层数量 |
| `A` | 固定金额模式下配置的每层报价币名义金额 |
| `lev` | 合约杠杆倍数；现货不适用 |
| `f_grid` | 交易环境提供的网格限价单保守手续费率 |
| `f_init` | 交易环境提供的初始化买入保守手续费率 |
| `buffer_base` | 系统统一风险规则给出的基础币安全余量 |
| `buffer_grid_quote` | 下限网格买入资金的报价币安全余量 |
| `buffer_init_quote` | 初始化建仓资金的报价币安全余量 |

创建策略时必须满足：

```text
L < P0 < U
ΔP > 0
```

初始价格层为：

```text
买入层价格 B[k] = floor_to_tick(P0 - k × ΔP)
条件：B[k] >= L，k = 1 ... N_buy

卖出层价格 S[j] = ceil_to_tick(P0 + j × ΔP)
条件：S[j] <= U，j = 1 ... N_sell
```

其中 `floor_to_tick` 向下按 `tick` 对齐，`ceil_to_tick` 向上按 `tick` 对齐。因价格取整产生重复价格层时，只保留一个价格层。

### 6.2 两种下单规模模式

#### 固定数量模式

每层订单数量固定：

```text
qty(p) = floor_to_lot(Q)
```

#### 固定金额模式

每层使用相同报价币名义金额，数量随价格变化：

```text
现货：
qty(p) = floor_to_lot(A / p)

线性合约：
qty(p) = floor_to_lot(A / (p × C))
```

每一层换算后都必须分别满足：

```text
qty(p) >= min_qty
p × qty(p) × C >= min_notional
```

任一价格层无法满足交易所最小数量或最小名义金额时，策略创建失败，不能静默改变该层配置。

### 6.3 现货初始仓位

#### 计划卖出所需基础币

为了保证价格逐层上涨到 `U` 时，每个卖出层都有现货可卖：

```text
planned_sell_base = Σ qty(S[j]), j = 1 ... N_sell

手续费以基础币扣除时：
base_fee_reserve = ceil_to_lot(planned_sell_base × f_grid + buffer_base)

手续费不以基础币扣除时：
base_fee_reserve = ceil_to_lot(buffer_base)

required_base = planned_sell_base + base_fee_reserve
```

如果手续费全部以报价币扣除，则 `base_fee_reserve` 可以只保留数量取整和安全余量；不能直接假设其恒为零，应以交易环境实际扣费规则为准。

#### 计划买入所需报价币

为了保证价格逐层下跌到 `L` 时，每个买入层仍有资金可以买入：

```text
planned_buy_quote = Σ [B[k] × qty(B[k])], k = 1 ... N_buy

手续费以报价币扣除时：
buy_fee_reserve = planned_buy_quote × f_grid + buffer_grid_quote

手续费不以报价币扣除时：
buy_fee_reserve = buffer_grid_quote

required_grid_quote = planned_buy_quote + buy_fee_reserve
```

#### 已有现货处理

只使用账户中未被其他策略、人工订单或资金冻结占用的可用库存：

```text
available_existing_base = 账户可用基础币 - 其他用途已分配基础币
allocated_existing_base = min(available_existing_base, required_base)
initial_buy_qty = ceil_to_lot(max(0, required_base - allocated_existing_base))
```

- `available_existing_base > required_base` 时，只向本策略分配 `required_base`，多余库存不进入网格账本；
- `0 < available_existing_base < required_base` 时，分配现有库存并买入差额；
- `available_existing_base = 0` 时，买入全部 `required_base`；
- 已有库存必须能取得账户权威成本；无法取得成本时，不能把该库存纳入本策略，应等待用户清理或选择明确的接管规则。

#### 初始化买入资金检查

设创建策略时第五档卖价为 `Ask5`，初始化买入的最大保护成本为：

```text
protected_initial_buy_quote = initial_buy_qty × Ask5
initial_buy_fee_reserve = protected_initial_buy_quote × f_init + buffer_init_quote

required_total_quote = required_grid_quote
                     + protected_initial_buy_quote
                     + initial_buy_fee_reserve
```

必须满足：

```text
available_quote >= required_total_quote
```

余额不足时策略创建失败，不允许通过减少下限买入层数、缩小初始化仓位或临时改变每层规模继续启动。

初始化买入以 `Ask5` 为保护限价：第一至第五档能够立即成交的部分先成交，剩余数量继续在 `Ask5` 挂单等待。初始化订单完全成交前，正式网格不得启动。

#### 初始仓位成本与基准价格

初始仓位成本和初始基准价格必须分开计算：

```text
existing_cost_value = allocated_existing_base × existing_average_cost
initial_buy_cost_value = Σ(initial_fill_qty[i] × initial_fill_price[i])
actual_initial_fees = 初始化成交实际费用折算后的成本影响

initial_position_cost = (existing_cost_value
                       + initial_buy_cost_value
                       + actual_initial_fees)
                       / actual_allocated_base
```

其中 `actual_allocated_base` 必须使用扣除基础币手续费后的实际净入账数量。

初始基准价格不使用上述加权成本：

```text
initial_buy_qty > 0：
initial_base_price = 初始化建仓订单的最后一笔成交价格

initial_buy_qty = 0 且可取得已分配初始仓位的最后建仓成交价：
initial_base_price = 该初始仓位的最后建仓成交价格

initial_buy_qty = 0 且无法取得可归属的最后建仓成交价：
initial_base_price = P0
```

`initial_position_cost` 只用于持仓收益，`initial_base_price` 只用于生成网格价格。

### 6.4 线性合约初始仓位与边界

每个价格层的合约数量按照 6.2 计算。完整价格区间内可能形成的买卖数量分别为：

```text
total_buy_contracts = Σ qty(B[k]), k = 1 ... N_buy
total_sell_contracts = Σ qty(S[j]), j = 1 ... N_sell
```

设创建策略前需要接管的已有合约净持仓为 `position0`，则全部计划订单成交后的仓位边界为：

```text
calculated_long_limit = position0 + total_buy_contracts
calculated_short_limit = position0 - total_sell_contracts
```

线性合约在边界价格下的保守名义金额为：

```text
long_notional = abs(calculated_long_limit) × L × C
short_notional = abs(calculated_short_limit) × U × C
required_notional = max(long_notional, short_notional)
```

按配置杠杆估算的最低初始保证金为：

```text
base_initial_margin = required_notional / lev
planned_order_notional = Σ[B[k] × qty(B[k]) × C]
                       + Σ[S[j] × qty(S[j]) × C]
estimated_order_fees = planned_order_notional × f_grid
required_margin = base_initial_margin
                + estimated_order_fees
                + funding_and_liquidation_buffer
```

实际创建检查必须使用交易所保证金阶梯、维持保证金率和风险限额重新计算，不能只依赖上述简化公式。必须同时满足：

```text
required_notional <= configured_max_notional
required_margin <= available_margin
lev <= exchange_max_leverage
```

### 6.5 已有合约持仓处理

已有合约持仓必须先确定归属：

- 属于同一策略的恢复持仓：恢复数量、方向、成本和最后完全成交价格，令其为 `position0`；
- 属于人工或其他策略的持仓：默认不允许新网格策略接管，策略创建失败；
- 用户明确选择接管时：使用账户权威数量和成本作为 `position0`，重新计算多空边界、名义金额和保证金；
- 用户明确选择清理时：先完成平仓并确认持仓归零，再以 `position0 = 0` 创建策略；
- 不允许在无法确定持仓归属或成本时假定 `position0 = 0`。

新建且账户无可接管合约持仓时：

```text
position0 = 0
initial_base_price = P0
```

合约已有持仓的平均成本只用于持仓收益核算；新策略的网格初始基准价格默认仍取 `P0`。恢复同一策略时，初始基准价格使用恢复的最后一个完全成交订单的最后一笔成交价格。

### 6.6 创建结果

创建流程必须保存以下计算结果，供运行、恢复和审计使用：

- 初始参考中间价 `P0`；
- 初始基准价格；
- 下单规模模式及逐层实际数量；
- 分配的现货基础币、报价币和初始仓位成本；
- 初始化买入订单及其全部成交明细；
- 合约初始净持仓、计算后的多空边界、杠杆、名义金额和保证金；
- 费用与安全余量；
- 未纳入策略管理的已有资产或持仓；
- 计算使用的交易所精度、费率、保证金阶梯和版本。

## 7. 现货需求

- 创建策略时，应根据初始参考价、网格上下限、网格间距和每层数量或金额，自动计算完整价格区间所需的基础币仓位与报价币资金；
- 初始基础币仓位应保证价格逐层运行至网格上限时，每一层仍有足够现货可卖，并在上限完成最后一笔计划卖出；
- 初始报价币资金应保证价格逐层运行至网格下限时，每一层仍有足够资金可买，并在下限完成最后一笔计划买入；
- 计算时必须包含交易精度、最小订单、实际手续费和资金预留，不能只按理论价格相乘；
- 初始仓位、分配给策略的基础币和报价币额度及其成本，应在创建策略时生成并保存，而不是由用户手工配置；
- 不得卖出超过实际可用库存的资产；
- 已挂卖单需要占用可卖库存；
- 已挂买单需要占用可用资金；
- 账户零库存或现有库存不足自动计算的初始仓位时，策略应在正式挂网格前买入缺少的数量；
- 初始化买入使用带五档价格保护的市价成交，实际成交不得超出启动时盘口第五档价格；
- 五档内流动性不足以立即完成初始化买入时，剩余未成交数量应以启动时第五档卖价作为保护限价挂单等待成交；等待期间策略保持初始化状态，不启动正式网格，也不向更高价格追单；
- 初始化买入完全成交后，结合已分配库存的权威成本和初始化买入实际成交，计算完整初始仓位的加权成本用于持仓收益；初始基准价格则使用完成初始化建仓订单的最后一笔成交价格，不能使用加权成本；
- 现有库存超过策略所需初始仓位时，只分配计算所得数量给本策略，额外库存不纳入本策略网格账本；
- 手续费扣基础币或报价币时都应正确影响余额和收益；
- 余额不足时不得反复提交必然被拒绝的订单。

## 8. 合约需求

- 合约配置必须包含杠杆倍数；
- 创建策略时，根据可分配保证金、杠杆倍数、网格边界、网格间距和每层数量或金额自动计算仓位上下限，不要求用户单独配置最大持仓；
- 允许按配置建立多头或空头持仓；
- 当前持仓和所有活动订单的潜在成交量不得突破自动计算的仓位上下限；
- 下单前检查保证金和最大名义金额；
- 资金费计入最终收益；
- 正确区分平仓和反向开仓；
- 第一阶段仅要求线性合约和净持仓模式；
- 交易环境不支持所需能力时，应拒绝启动或明确降级，不能静默改变语义。

## 9. 成交与订单需求

- 每一笔成交都能被独立处理；
- 支持一个订单发生多次部分成交；
- 部分成交不得更新基准价格；
- 订单完全成交后，使用完成该订单的最后一笔成交价格更新基准价格；整笔订单的加权成交成本只用于持仓和收益核算；
- 成交和撤单同时发生时不能遗漏成交；
- 重复收到同一成交时不能重复计算持仓或收益；
- 成交后及时更新库存、持仓、资金占用和收益；
- 完全成交后释放对应活动订单位置；
- 部分成交后只释放已经成交的部分；
- 每个订单具有唯一且可追踪的客户订单编号，并能确认该订单是否由当前策略实例创建；
- 完整处理新建、部分成交、完全成交、撤单、过期和拒绝状态；
- 撤单未确认时，相关资金或仓位仍视为被占用；
- 订单拒绝后应退避，避免形成拒单风暴；
- 停止策略时停止提交新单并处理遗留订单。

## 10. 收益需求

### 10.1 网格收益

网格收益表示由本策略产生的买卖成交完成配对后形成的已实现收益。初始化买入形成的仓位出售收益、人工调仓或其他策略产生的持仓收益不应混入网格收益。

### 10.2 持仓收益

持仓收益包括当前未平仓部分的浮动收益，以及初始化仓位或非网格来源持仓产生的收益。

### 10.3 总收益

总收益应综合网格收益、持仓收益、手续费、资金费及其他明确记录的交易成本或收入，并能与引擎账户权益核对。

### 10.4 展示指标

- 累计网格收益；
- 当前持仓收益；
- 累计总收益；
- 累计手续费和资金费；
- 当前持仓及持仓成本；
- 成交次数和完整网格次数；
- 当前活动买单、卖单数量。

## 11. 风险控制需求

- 自动计算的仓位上下限和最大名义金额；
- 最大活动订单数；
- 现货余额及库存检查；
- 合约保证金检查；
- 最大连续拒单和下单失败次数；
- 行情长期不更新时暂停下单；
- 盘口异常或价格无效时暂停下单；
- 订单长时间未确认时触发异常处理；
- 账户持仓与策略记录不一致时暂停新单；
- 连接中断时停止新增风险；
- 人工停止和紧急停止能力。

## 12. 启动、停止与恢复

启动前应检查行情、品种精度、余额、持仓、活动订单和本地记录。应支持：

- 清理启动：撤销遗留订单后重新开始；
- 接管启动：核对并继续管理已有订单和持仓；
- 严格启动：发现遗留订单或状态不一致时拒绝启动。

停止后不得提交新订单；根据配置撤销本策略订单，保存最终订单、成交、持仓和收益状态，并区分正常停止、风控停止和异常停止。

## 13. 回测需求

- 支持订单延迟、行情延迟和订单队列位置；
- 支持 maker/taker 手续费和部分成交；
- 支持现货和线性合约账户模式；
- 回测与实盘使用相同的策略行为；
- 不假定所有限价单都能成交；
- 输出订单、成交、持仓和收益明细；
- 支持比较不同层数、间距和持仓限制；
- 明确记录手续费、返佣、延迟和成交模型。

## 14. 可观测性与审计

系统应记录：

- 基准价格变化及成交后的补单记录；
- 下单、撤单、拒单和成交事件；
- 风控阻止下单的原因；
- 账户与策略状态不一致事件；
- 网格收益、持仓收益和总收益变化；
- 策略启动、恢复、暂停和停止原因。

报表应能从订单和成交记录追溯收益来源。

## 15. 验收标准

### 15.1 网格行为

- 配置买卖各 3 层时，正常情况下每侧最多维护 3 层；
- 数量模式下各层按配置数量下单；金额模式下各层按配置名义金额换算数量，并满足交易所数量精度和最小订单要求；
- 部分成交不会更新基准价格；
- 订单完全成交后，基准价格更新为完成该订单的最后一笔成交价格，原有未成交订单继续保留，并按配置补充成交产生的订单空缺；
- 没有新成交时，市场行情变化不会导致网格中心持续漂移、撤销原有订单或反复重挂；
- 策略不会撤销或修改其他策略、人工或外部系统创建的订单；
- 成交后能在规定刷新周期内补充缺失层。

### 15.2 现货与合约

- 零库存现货会先在五档价格保护内完成自动计算的初始化买入，初始化完成前不会启动正式网格；
- 初始仓位能够覆盖价格逐层上涨到网格上限所需的全部计划卖出；
- 预留报价币能够覆盖价格逐层下跌到网格下限所需的全部计划买入；
- 五档内流动性不足时，剩余初始化数量会在第五档保护价挂单等待，完全成交前不会启动正式网格或向更高价格追单；
- 活动卖单总量不会超过可卖库存；
- 资金不足时不会重复提交超额买单；
- 合约配置包含杠杆倍数，活动订单全部成交的最坏情况下仍不突破自动计算的仓位上下限；
- 资金费和手续费正确影响总收益。

### 15.3 成交与收益

- 多次部分成交不会漏记或重复记账；
- 多次部分成交期间基准价格保持不变，只有完全成交后按最后一笔成交价格更新一次；
- 撤单成交竞态不会遗漏有效成交；
- 重复成交事件不会重复改变持仓和收益；
- 网格、持仓、费用、资金费和总收益可以相互核对；
- 策略总收益能够与账户权益变化对账。

### 15.4 异常与恢复

- 连续拒单不会产生高频重试；
- 行情失效时停止新增订单；
- 持仓不一致时暂停新单并告警；
- 重启后能够按配置清理、接管或拒绝启动；
- 紧急停止后不再增加风险敞口。

## 16. 上游参考及使用边界

- [High-Frequency Grid Trading](https://hftbacktest.readthedocs.io/en/latest/tutorials/High-Frequency%20Grid%20Trading.html)
- [hftbacktest 官方仓库](https://github.com/nkaz001/hftbacktest)

采用有限活动网格、按持仓控制单边风险，以及在回测中考虑延迟和队列位置等思想。网格中心不采用官方示例中持续跟随中间价的方式，而是使用最新成交价格作为基准价格。

不直接照搬教程中的价格型订单编号、仅依赖轮询清理订单、特定 maker 返佣假设，以及缺少重启恢复和账户对账的教学实现。

## 17. 待业务确认事项

1. “挂 N 层”表示买卖两侧各 N 层，还是两侧合计 N 层；
2. 买卖两侧是否允许配置不同层数；
3. 网格间距是否统一使用 tick 数；
4. 是否需要展示逐层网格收益；
5. 重启默认采用清理、接管还是严格拒绝；
6. 风控停止时是否自动撤单，是否允许自动平仓；
7. 一笔订单完全成交后，是补充同方向订单、反方向订单，还是按买卖两侧目标数量补足；该选择将决定活动层数如何长期保持；
8. 初始化现货仓位需要预留多少手续费和安全余量，以及账户余额不足完整覆盖上下限时是否直接拒绝创建策略；
9. 按固定金额下单时，金额是报价币名义金额还是结算币金额；第一阶段建议现货和线性合约均使用报价币名义金额。
