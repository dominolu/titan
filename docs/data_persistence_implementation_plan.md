# Titan 数据持久化实施计划

版本：v0.9  
日期：2026-10-28  
状态：M1–M4 首轮范围已完成；候选 07 故障后安全恢复及回归通过；真实补验仍停止，两条真实占用保留
设计依据：[数据持久化设计 v0.9](data_persistence_design.md)  
实现基线：`5997364864861fdd5d8c649b93e54161018f703d` 加工作区修改；完整源码身份见[M1 验证记录](verification/2026-10-27/data-persistence/m1/README.md)、[M2 验证记录](verification/2026-10-27/data-persistence/m2/README.md)和[M3 验证记录](verification/2026-10-28/data-persistence/m3/README.md)

本计划将“恢复点统一存 SQLite、策略无感知、后端按能力切换”拆成可独立审查和验收的工作包。M1 完成恢复闭环，M2 完成本地事实、历史回测、查询和对象闭环；M3 已完成真实 PostgreSQL/S3 与双向切换验收，不能以本地通过代替后端切换验收。

## 1. 实施范围与阶段门槛

| 阶段 | 工作包 | 交付结果 | 阶段门槛 |
| --- | --- | --- | --- |
| M0 文档 | 本次整理 | 设计、任务依赖、迁移及验收定义 | 文档相互引用，当前状态与目标能力明确 |
| M1 SQLite 恢复 | P01–P04 | 恢复点/代次 SQLite 化，宿主和管理固定引用贯通，旧文件迁移及备份工具 | 无真实账户恢复与故障矩阵通过；文件不再是正常写入或自动回退后端 |
| M2 本地完整闭环 | P05–P09 | 实盘模拟与回测统一事实采集、本地历史查询、对象及数据集清单 | 引擎结果、持久化完整性、管理查询和报告一致，策略无需保存结果代码 |

本期恢复存储始终使用节点本地 SQLite；M3 不将恢复迁往 PostgreSQL 或 S3。管理目录保持 SQLite，保留领域仓储接口；不因历史后端已切换而宣称管理数据库的第二实现已完成。

M1 已交付 `StrategyRecoveryStore`、`RecoverySubmitToken`、`RecoveryPointRef`、schema v1、有界 SQLite writer、代次隔离、固定引用恢复及维护 CLI。M1 已验证的故障子场景和全阶段矩阵的剩余范围见[验收记录](verification/2026-10-27/data-persistence/m1/README.md)，P13 的软件故障与完整争用预算门禁已在 [M3 本轮验收](verification/2026-10-28/data-persistence/m3/README.md)完成；不声称已执行物理断电。

M2 已交付独立 `titan-persistence` crate 的事实/查询/对象端口、SQLite 统一事实与来源完整性、引擎自动采集、Parquet reader/writer、内容对象/结果登记及维护工具。管理页面与回测共用固定上界查询，权益图显式读取最新采样；策略及 SDK 不增加持久化代码。最终源码 540 个文件的字节对照一致，34 个门禁步骤通过，具体矩阵和限制见[M2 验收记录](verification/2026-10-27/data-persistence/m2/README.md)。

本期不实现任意中断回测续跑、ClickHouse、分布式恢复主备、自动接管账户或通用消息总线。新恢复后端属于后续独立设计和验收，不是本期遗留的隐式必选项。

## 3. 代码迁移顺序与兼容窗口

1. P01 冻结契约和 schema；先使 Runtime 依赖抽象，再增加 SQLite 实现。迁移中的文件实现仅服务既有兼容测试，不新增功能。
2. P02/P03 贯通 SQLite 后，所有新启动使用 SQLite。旧配置只能通过明确的兼容解析或维护入口迁移；错误配置不能静默创建一个空库并按全新运行放行。
3. P04 用旧字节 fixture 验证迁移，再停止旧宿主、保留账户占用和固定文件证据，进行离线切换。没有完成切换的节点继续使用其原有版本，不能同时对同一命名空间启动新旧宿主。
4. M1 完成后，删除正常运行的文件 writer、`.generation` 写入及自动文件 fallback。保留明确命名的导入导出和旧 reader；同步更新示例、配置、错误码及操作说明。
5. P05–P08 移动采集位置和读取入口，保持引擎计算及原生策略文件。现有日志、Registry、管理 Operation、业务观测和数据准备回执逐项复用，不新增平行控制入口。
6. M3 后端通过同一契约后才开放对应 driver 配置。未构建 feature 或能力未验收时给出明确错误，不能接受配置后退回本地实现。

对外 `recovery_point_sha256` 保留“原始恢复载荷字节”的含义。旧文件位置变为经核验的旧引用别名，新请求使用固定 record 引用；不原地改旧签名文件、载荷、Operation 请求或幂等摘要。引用和 DTO 若有不兼容变化，显式版本化并生成配套前端类型。

## 4. 验收矩阵

所有构建和非实盘自动验证在 `192.168.3.88` 执行，以下“模拟实盘”均指不接真实账户的原生宿主/connector 模拟；P14 的真实账户自动验收只在已授权实盘服务器执行。

| ID | 场景与注入点 | 必须证明 | 归属 |
| --- | --- | --- | --- |
| A01 | 同一已签名策略文件，存储配置切换 | 策略文件 SHA256/ABI 不变，不新增策略数据库调用；回调与领域结果符合冻结输入 | P01、P03、P12 |
| A02 | 列值/原始 BLOB、内部 checksum、schema、编译摘要、绑定分别篡改 | 任一不符均拒绝恢复；数据库有该行不代表可恢复 | P02–P04 |
