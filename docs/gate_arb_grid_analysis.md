## 实际模型

主要实现位于 `app/services/contract_grid_service.py`，接口模型位于 `app/domain/contract_grid.py`，回归场景位于 `tests/test_contract_grid_unittest.py`。PRD 不是当前实现的完整事实来源：实现已加入在线 reconfigure，而早期 PRD 仍称运行中不能修改参数。

`compute_grid_orders` 使用上下界和完整区间格数计算间距：等差为 `(U-L)/N`，等比为 `(U/L)^(1/N)-1`。每次围绕当前锚点只维护一张下买和一张上卖；不是预铺 N 张订单。资金分配规模是 `M×杠杆/N`，初始每单数量再除以创建时价格。默认实际代码把这个数量保存下来，后续 `_order_qty` 直接返回该数量；不能因早期 PRD 写有 fixed-notional 就认为实盘已经逐单按金额重新定量。

方向性初始化按价格所在格位 `k` 计算：多头为 `(N-k)×单笔数量`，空头为 `k×单笔数量`；中性不建初始仓位。初始化使用市价单，多次尝试补足；代码还允许已建部分仓位后，剩余低于最小量时继续启动。

`_submit_live_grid_orders_locked` 的多头卖单受当前持仓限制、买单受可用余额限制；空头对称。中性卖单受 `_accumulated_neutral_qty` 限制，因此其实际行为是从零累积买入后才能卖出，不是真正对称双向中性。完整成交后 `_advance_grid_after_fill_locked` 撤对侧，`_reset_grid_after_fill` 以订单累计均价更新锚点并重挂。部分成交不推进完整轮次。

运行时有交易所精度归一化、WS 成交处理、REST 对账、重复订单清理、缺失订单补挂、初始仓位、停止平仓、收益配对、资金费及通知；这些功能分散在订单服务、账户服务和本服务中。在线 reconfigure 允许改边界、格数和资金，先严格撤单，再按新目标补仓并重新挂单。多头上边界平仓后完成，低于下边界停止加买；测试覆盖了边界平仓、重复成交、稀疏撤单响应、恢复及归属成本。

## 迁移时修正的风险

| 源码行为 | 影响 | 新实现 |
| --- | --- | --- |
| `_cancel_counterpart_order` 在任意撤单异常分支调用 `_mark_grid_order_cancelled`，包括不属于幂等撤单的异常 | 旧单可能仍活跃，新一轮已挂出，持仓和订单数超预期 | 只靠权威订单终态释放引用，未知结果保持占用并对账 |
| 中性模式只允许卖出累积买入量 | 与真正双向中性是两套业务语义 | 默认双向中性；`neutral_mode=inventory_only` 保留源项目库存约束 |
| 初始化允许不足量继续启动 | 实际初始库存与原计划不一致 | 必须确认达到计划数量；明确终态后才补余量，不静默改变目标 |
| 资金和订单规则嵌入异步服务、数据库及 REST 调用 | 无法直接放到原生热路径 | Numba 只保留决策、意图引用和配对业务账本；平台继续负责事实与执行 |
| PRD 的部分能力与当前实盘代码不同 | 仅按文档移植会得到另一套策略 | 对照实际方法与测试，显式记录差异和配置选择 |

这不是对源项目进行修复；上述行为仅影响新策略设计。

## Titan 中的交付

入口为 [`strategies/grid/strategy.py`](../strategies/grid/strategy.py)，参数示例为 [`parameters.json`](../strategies/grid/parameters.json)，详细行为与参数见 [使用说明](../strategies/grid/README.md)。

保留源策略的默认成交均价锚点和成交后撤剩余挂单。增加 `last_fill` 和 `retain`，以覆盖 Titan 既有网格需求中“最后一笔成交锚点”和“旧挂单保留”的行为；没有改写既有需求文档。增加多层、真正固定名义规模、退避、待确认订单预占、风险上限和有保护价格的初始化/退出。

原生 V13 宿主原先以“无活动订单、无待交付成交”为停止完成条件。网格可能已经撤完单，但还在等待重试时点或持仓投影，此时不能提前关门。新增通用 `STOP_BARRIER` 能力和 `ctx.complete_stop()`，让策略在业务确认完成后显式释放停止屏障；未声明该能力的旧策略保持既有停止流程。离线 adapter 同样支持等待后续确认。

代码不访问网络或数据库，也不改变账户杠杆和保证金模式。手续费、资金费、净权益和精确风险阶梯仍是平台职责。当前 V13 回调没有完整费用事实，策略只输出明确标记的毛收益，避免伪造净收益。Web 界面、通知、热调参和现货资金分配不属于此次原生策略交付；源项目已有功能不等于本策略对这些外部服务提供了替代。

验证证据见 [2026-10-22 网格验证](verification/2026-10-22/grid/README.md)。验证仅在指定编译服务器执行，实际结果以报告为准；没有启动实盘策略或执行真实下单。

## 全面复核后的补充

`1.1.0` / schema `2` 修复了首版中的成交/持仓确认竞态、累计量回退、未知成交被账户全局水位吞掉、减仓保证金误拦、保留旧单时可能交叉报价、无进展 IOC 无限重试以及恢复误拒已确认撤单等问题。新增 `allocated_fixed_qty`，在初始盘口按 `M×杠杆/N/P0` 计算一次单笔数量并冻结；这与源项目的实盘数量模式一致，区别于逐单重算数量的 `allocated`。

全面审查及新的验证证据见 [复核报告](verification/2026-10-22/grid-review/README.md)。首版报告保留为历史证据；新版本恢复能力有显式 manifest 门禁，旧状态不做自动迁移。

## 真实历史回测后的修正

实际 BTCUSDT 永续历史成交与盘口回放发现：`1.1.0` 将保护性平仓和开仓共用无进展/拒单次数上限，暴跌与高延迟下可能停止重试并留下库存。`1.2.0` / schema `3` 改为保护性退出独立总时限，保持原滑点、reduce-only、事实确认和退避限制，期限不随行情、重试或恢复延长。编译链同时补上显式数学库依赖与未解析符号拒绝，避免制品依赖宿主预加载的 libm。历史数据、收益、回撤和风险敞口见 [历史回测报告](verification/2026-10-22/grid-history/README.md)。
